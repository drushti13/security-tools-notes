# Burp Suite

I started using Burp Suite while learning web application security through **PortSwigger Web Security Academy** and **TryHackMe**. It has become the tool I use the most for testing web applications. I have solved multiple PortSwigger labs using Burp Suite, covering topics such as authentication vulnerabilities, access control, information disclosure, request smuggling, clickjacking, and directory traversal. I have documented the writeups for these labs in my **PortSwigger Labs Writeups** repository.

Burp Suite allows me to intercept, analyze, and modify HTTP requests and responses, making it an essential tool for understanding how web applications communicate with the server and how vulnerabilities can be identified through manual testing.

## Proxy

The Proxy module acts as an intercepting proxy between the browser and the target application. It is the first tool I use in almost every lab.

I use it to:

* Intercept HTTP requests and responses
* Modify request parameters before forwarding them
* Inspect cookies and session tokens
* Analyze request and response headers
* Send interesting requests to other Burp modules

## Target

The Target tab provides a site map of the application after browsing it through Burp Proxy.

I use it to:

* Understand the application's structure
* Discover hidden endpoints
* Review captured requests and responses
* Navigate the application's functionality more efficiently

## Repeater

Repeater allows me to manually modify and resend requests as many times as needed while observing how the application responds. I use it extensively when testing authentication, access control, IDOR, SQL injection, and other input-based vulnerabilities.

## Intruder

Intruder automates sending multiple requests with different payloads. I have mainly used it for username enumeration, password brute forcing, and fuzzing parameters in PortSwigger labs.

The attack types I have used include:

* Sniper
* Battering Ram
* Pitchfork
* Cluster Bomb

## Decoder

Decoder is useful when working with encoded data during testing.

I use it to:

* Encode and decode Base64
* URL encode and decode values
* Decode hexadecimal data
* Convert data into different formats

## Comparer

Comparer helps identify differences between two requests or responses.

I mainly use it to compare:

* Authentication responses
* Username enumeration responses
* HTTP requests after modifying parameters
* Similar responses with different server behavior

## Sequencer

Sequencer analyzes the randomness of tokens generated by a web application, such as session IDs and CSRF tokens. Although I haven't used it much in labs yet, I understand how it can be used to determine whether tokens are predictable.

## Extensions

Burp Suite supports extensions through the BApp Store, allowing additional functionality to be added when needed. Extensions can automate repetitive tasks and add support for different testing techniques.

## My Workflow

The workflow I usually follow while solving PortSwigger labs is:

1. Browse the application through Burp Proxy.
2. Identify an interesting request and send it to Repeater or Intruder.
3. Modify parameters or payloads depending on the vulnerability being tested.
4. Analyze the application's response.
5. Verify the vulnerability and complete the lab.

Using Burp Suite regularly has helped me understand how web applications process requests, manage sessions, validate user input, and enforce access controls. It has also improved my ability to manually identify and verify web vulnerabilities instead of relying only on automated scanners.
